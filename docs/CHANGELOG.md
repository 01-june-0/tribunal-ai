# 변경 이력

Tribunal AI는 [AI DEV DIRECTOR](https://github.com/digilogd-cmd/ai-dev-director) v3.1.8(MIT)에서 갈라져 나왔습니다. 이 문서는
그 뒤에 무엇을 바꿨는지, 원본에서 물려받은 것 중 무엇을 검증하지 않았는지를 적습니다.

## 원본에서 물려받은 것

흐름의 뼈대는 원본의 것입니다: 지시서, 파일 제안 방식의 제작, 격리 작업 사본, 범위 검사, 독립 감리, 자동 수정, 작업(여러 단계),
대리 판단 정책, 결과물 적용과 폐기, AI 상태 관리와 장애 시 교체, 호출 장부, 콘솔 서버와 브리지.

### 실제로 돌려 확인하지 않은 것

아래는 코드와 테스트는 있지만 **실제 작업이나 실제 화면으로 확인한 적이 없는 것**입니다. 실제로 확인한 것은 macOS에서
`director do`와 콘솔로 돌린 작업들입니다(통과, 자동 수정, 마침 검사에서 멈춤, 시작 전 · 제작 후 승인, 거절, 손으로 적용,
충돌 건너뛰기, 폐기, 두 단계로 이어지는 `standard` 작업과 그 결과물의 적용, 작업 사본의 제외 목록, 작업 정지 버튼, 콘솔을 껐다
켠 뒤 이어 하기, 자동 적용과 그 뒤의 작업 사본 · 브랜치 정리(두 단계 작업 포함), `deep` 프로필의 세 단계 작업과 자동 적용 `on_done`, 정지한 작업의 작업 사본 지우기, 충돌 · 삭제 안내,
충돌을 건너뛴 적용과 그때 작업 사본이 남는 것, 적용 뒤 테스트가 실패해 되돌리는 경우, 감리 AI의 독립 테스트, 채팅의 "멈춰",
`director resume`, 정지한 작업의 이어서 시도(두 단계 작업의 2단계 판단 중에 정지한 경우 포함), 제작 후 승인 거절,
휴대폰 폭의 변경 내용 창과 AI 설정, 영어 화면의 승인 요청, 이미 쓰이는 포트 · `TRIBUNAL_PORT`, 한도 경고, 움직임 줄이기,
WebGL을 쓸 수 없을 때의 2D 장면 · 줌인 · 구름 속 화면, 전체 화면 모드, 큰 프로젝트에서 MAKER에게 보내는 파일 고르기,
빈 폴더 · git 없는 폴더에서 작업을 끝까지, 콘솔 밖 `director mission`과 그 정지, 결제 SDK 가져오기 · 결제 호출로 걸리는 돈 관련
검사, 프로젝트별 빌드 · 린트 명령). 콘솔 밖에서 돌던 AI 호출은 콘솔이 끊을 수 없어 그 호출은 끝까지 가고, 그 뒤로는 아무것도
시작하지 않음.
"감리 독립성 낮음" 표시는 실제 역할을 바꾸지 않고, 데모 콘솔에서 역할 응답만 바꿔 화면을 그려 확인함. 같은 방법으로 도구를
많이 쓰는 호출(기록 260건 중 최근 200건만 보이고 전체 수가 함께 나옴)과 오류가 난 도구 호출이 구름 속 화면과 상세 패널에
나오는 모습, 핵 속 화면에서 실패하는 테스트 출력이 실행 중에 나오고 끝나면 실패로 바뀌는 모습을 확인함.
AI가 빠지거나 이상하게 답하는 경우는 실제 AI 대신 `claude` · `codex` · `agy` 이름의 가짜 CLI를 앞세워, 저장소 사본과 따로 둔
데이터베이스로 `director mission`을 끝까지 돌려 확인함(2026-11-23, 시나리오 25개): 한도 소진 · 로그인 풀림 · 상태 확인 실패로
AI 하나 · 둘 · 셋이 빠지는 경우(시작 시점, 실행 도중, 첫 설계 호출, 대리 판단을 끈 경우), 형식이 깨진 답과 출력 없는 종료의 재시도와
다른 AI로 넘기기, Antigravity 출력 한도의 압축 재시도, 멈춘 CLI의 시간 초과(출력 없음 5초 · 전체 8초로 줄여서)와 TIMEOUT으로
끝나는 실행, 감리 · 판단 단계의 같은 경우들. 실제 CLI의 오류 문구가 가짜와 다를 수 있다는 점은 남음.
실제 AI로는 2026-11-24에 확인함: 감리 AI의 독립 테스트가 실패해 P1이 되고 수정 회차로 이어지는 경우(제작만 버그를 심은 가짜로,
다음 회차 감리에 지난 실패가 전해지는 것까지), 모두 실제 AI로 `director run` 한 번(통과, 감리 테스트 포함 26개), 설계 시간 제한을
8초로 줄여 실제 Claude · Codex 호출이 끊기고 프로세스가 남지 않는 것.
작업 기록 없이 끝난 결과물(작업 밖 `director run`)을 충돌한 상태로 콘솔에서 적용 → 보류 → 다시 눌러 건너뛰기 적용까지 화면으로 확인함
(2026-11-24, 가짜 CLI로 만든 결과물과 따로 띄운 콘솔): 내 파일은 그대로, 나머지만 적용, 적용 뒤 테스트, 작업 사본 · 브랜치 남김.
AI 설정의 계정 칸은 사용자가 직접 눌러 확인함(2026-11-24): 이메일 보기와 20초 뒤 가림, Antigravity 터미널에서 열기,
Codex 로그아웃 → 로그인, 계정 변경, 작업 중 로그아웃 거절. 자세히 탭의 새 대화, 결과물 창에서 적용하고 검증, 폴더 선택 창(홈 폴더 거절), 경로 직접 입력, 작업 결과 폴더 열기도 직접 확인함.

## 바꾼 것

### 실행 환경

- macOS에서 동작하도록 고치고 실제 작업으로 검증.
- 콘솔 포트가 다른 프로그램에 잡혀 있으면 다음 빈 포트를 자동으로 사용. 이미 떠 있으면 그 주소를 알려 줌.
- 컴퓨터마다 다른 값은 git에 올리지 않는 `config.local.yaml`, `companion.local.json`에.
- 지어낸 작업으로 채운 읽기 전용 데모 콘솔(`scripts/demo_console.py`).
- 테스트가 만든 실행 폴더를 끝날 때 정리.

### 엔진

- **가벼운 호출** — Claude는 MCP 서버 · 스킬 없이 읽기 도구만(호출당 입력 약 51,000 → 8,000 토큰), Codex는 플러그인 · 메모리 ·
  훅 · 연결 앱 없이(감리 1회 약 52,000 → 7,000 토큰).
- **감리 AI의 독립 테스트** — MAKER가 쓴 테스트만으로 자기 코드가 통과하는 것을 막기 위해, INSPECTOR가 제안한 테스트를 Tribunal이
  실행. 완료 기준마다 테스트를 요청.
- **빠른 수정** — 테스트가 실패한 회차는 감리와 판단을 건너뛰고 바로 MAKER에게. 건너뛴 회차는 수정 횟수에 넣지 않음.
- **검증 시간 제한**을 설정으로(`verification.timeout_sec`). Claude의 설계 · 감리 호출은 출력 없는 시간 감시를 적용하지 않음.
- **판단에 테스트 출력 끝부분을 전달.**
- **돈 관련 코드 검사를 정밀하게** — 새 파이썬 파일이 직접 정의한 함수는 이름(`order_send` 등)만으로 멈추지 않음. 기존 파일
  수정, 모듈을 거친 호출, 이름이 다른 것에 연결될 수 있는 경우는 그대로 멈춤.
- **호출별 모델 · 추론 강도 기록.**
- **테스트 출력의 실시간 기록** — 테스트가 도는 동안 출력을 조각 단위로 남김. 판정에 쓰는 결과는 지켜볼 때와 아닐 때 동일.
- 모든 검증을 같은 환경(`PYTHONUNBUFFERED=1`)에서 실행.
- **기본 역할 배정 변경** — 제작 Codex, 감리 Antigravity(원본은 제작 Antigravity, 감리 Codex). AI 하나를 쓸 수 없을 때 역할을 옮기는
  규칙을 배정과 무관하게 동작하도록 고침.
- **작업 사본에 들어간 추적 안 된 파일을 기록하고 화면에 표시**, **제외 목록 설정**(`snapshot_exclude`), **폐기할 때 실행 브랜치도 삭제**.
- **여러 단계 작업의 변경 내용 보기** — 결과물을 적용하면 앞 단계의 파일도 함께 쓰이는데 화면에는 마지막 단계의 변경만
  나오던 문제. 적용 전 화면이 실제로 쓰일 파일 전체와 원본 대비 변경을 보여 주고, 몇 단계의 변경인지 표시.
- **작업 사본과 실행 브랜치 자동 정리** — 결과물을 원본에 적용하면 그 작업의 모든 단계의 작업 사본과 브랜치를 지움(충돌한 파일을
  건너뛴 경우는 남기고, 다 쓴 뒤 결과물 카드의 **작업 사본 지우기**로 정리). 폐기하면 앞 단계의 것도 함께 지움. 아무것도 통과하지 못하고 멈춘 작업은 카드의 **작업 사본 지우기**로 정리.
  적용할 때 쓴 파일과 변경 내용은 실행 기록에 남아 작업 사본이 없어도 다시 볼 수 있음.
- **시간 초과로 끝난 테스트의 표시** — 기록 목록과 상세에 "테스트 결과 없음" 대신 "시간 초과 · 제한 시간 안에 끝나지 않음".
- **끝나지 않은 단계의 이름** — "2단계 · DECIDING" 대신 "2단계 · 판단 중에 멈춤"(돌고 있으면 "판단 중").
- **AI에게 보내는 글의 이름** — 지시문과 안전 장치 문구에 남아 있던 "the Director"를 "Tribunal"로. ARCHITECT가 사용자에게
  "Director의 타임아웃"이라고 말하던 원인.
- **MAKER에게 보내는 읽기 전용 파일 고르기** — 전에는 고칠 수 없는 파일을 이름순으로 6만 자까지 모두 보냈음. 이제 지시서가 이름을
  댄 파일, 고칠 파일이 가져오거나 고칠 파일을 가져오는 파일, 고칠 파일의 테스트, 같은 폴더의 파일 순으로 보내고, 관계없는
  파일은 모두 합쳐 2만 자까지만 보낸 뒤 나머지는 경로만 알려 줌. 연습용 같은 작은 프로젝트에서는 달라지는 것이 없고(전부 들어감),
  큰 프로젝트에서만 줄어듦. 관계없는 파일이 21만 자인 연습용 프로젝트에서 지시문이 62,575자 → 19,553자(약 69%↓)로 줄었고,
  실제 작업도 자동 수정 없이 통과(고칠 파일을 쓰는 쪽의 테스트 포함).
- **대리 판단을 끈 설정의 대체** — 설계 AI가 실패하면 예전 배정(Codex → Claude)만 가정하던 것을, 쓸 수 있는 다른 AI로 넘기도록.
  설정 파일에 역할이 없을 때의 코드 안 기본값도 지금 배정(Claude · Codex · Antigravity)으로.
- **README 영어 요약**.
- **작업 상태 이름** — 정지한 작업이 카드와 "지금" 칸에 "STOPPED"로 나오던 것을 "정지함"으로.
- **"다시 요청" 초안의 영어판** — 영어 화면에서 "ARCHITECT에게 다시 요청" 버튼이 넣어 주는 초안도 영어로.
- **정지와 겹친 복구 시도** — 복구 중인 AI의 시도 기회를 잡은 직후 정지로 호출이 막히면, 그 기회를 돌려줌(전에는 10분 동안 묶임).
- **감리 테스트의 돈 관련 검사** — 감리 AI가 제안한 테스트가 **이번 실행에서 새로 만든** 파일의 `order_send` 같은 함수를 가져다
  쓰면, 그 함수의 실제 정의를 함께 보고 판단함. 돈을 움직이지 않는 평범한 함수면 받아들이고, 정의 쪽에 결제 코드가 있으면 거절.
  원래 프로젝트에 있던 파일의 함수는 전처럼 이름만으로 거절(패턴에 안 걸리는 방식으로 주문을 낼 수 있어서).
- **Python 3.9 확인** — 테스트 모음을 3.9에서도 돌려 통과(3.11 이상 라이브러리로 설정 문법만 검사하는 테스트 1개는 건너뜀).
- **진단 도구를 지금 배정에 맞게** — `scripts/`의 세 도구가 예전 배정(Codex · Claude만 설계 AI)을 가정했고, 역할 확인 도구는
  AI가 만든 코드를 이 프로그램 안에서 바로 실행했음. 이제 공통 모듈(`core/role_checks.py`)이 실제 실행과 똑같은 방식으로 AI를
  만들어 확인하고, AI가 만든 코드는 별도 프로세스에서만 실행. `cli_diagnostics.py`는 지금 배정의 세 역할을 한 번씩,
  `test_role_cli_smoke.py`는 세 AI × 세 역할(골라서 가능), `retry_transport_run.py`는 사용법과 안내를 정리. 확인은 실제
  실행과 같은 git 폴더에서 하고, 감리가 실패를 판정 형태로 돌려주는 경우(설정 오류 · 시간 초과)도 실패로 셈. 지금 배정의 세 역할과
  Codex의 설계 · 감리, Antigravity의 제작을 실제로 돌려 확인.
- **`director do`가 콘솔의 거절을 지키도록** — 콘솔이 요청을 거절하면(받지 않는 폴더, 바쁜 프로젝트 등) "콘솔이 없다"고 보고
  명령줄 안에서 그대로 돌리던 것. 거절한 규칙을 그대로 돌아가는 셈이었음. 이제 거절 이유를 보여 주고 끝냄. 콘솔에 닿지 못해 명령줄
  안에서 돌 때도 콘솔과 같은 폴더 규칙을 지키고, `--no-apply`도 지킴(전에는 무시하고 원본에 적용했음). git이 아닌 폴더는 콘솔에
  프로젝트로 준비해 달라고 함께 보냄(`-p`로 지정한 폴더만, 다른 저장소 안의 폴더는 제외). 요청을 보낸 뒤 응답 전에 연결이 끊기면
  같은 작업이 두 번 돌지 않도록 명령줄 안에서 다시 돌리지 않음. `director mission`에도 `--no-apply`.
- **외부 지시의 폴더 규칙** — 거부 목록의 폴더를 대소문자만 바꿔 지정해도 거부, 허용 폴더 자체(`~/Developer` 등)는 대상이 아님.
- **아이콘 요청** — 콘솔을 처음 열 때 브라우저가 찾는 `favicon.ico`에 404 대신 빈 응답.
- **공개 전 정리** — 기본 설정의 허용 폴더에서 원본 작성자의 경로를 빼고 일반적인 위치로(`~/Developer`, `~/work`, `~/projects`),
  예시 이메일을 중립적인 것으로, `.gitignore`에 가상환경 추가, README와 콘솔 문서에 데모 화면 그림.
- **예전 이름 호환 삭제** — 외부 지시 입구의 옛 이름(설정 절, 주문 표, 토큰 파일, 작업 출처 값)을 읽어 주던 코드를 지움.
- **쓰이지 않는 스타일 정리** — 자세히 탭 스타일에서 어디에도 쓰이지 않는 규칙 18개 삭제.
- **통과한 단계 없이 끝난 작업** — 실패한 시도의 작업 사본을 결과물로 취급해 "적용 대기 · 원본에 적용"을 내놓던 것. 통과한
  단계가 있을 때만 결과물로 보여 줌. ARCHITECT가 완료라고 판단했지만 통과한 단계가 없는 작업은 그 사실을 알려 주고
  **작업 사본 지우기**를 내놓음.
- **정지한 실행의 표시** — 자세히 탭이 정지한 작업을 "제작 중 · 4분"처럼 진행 중으로 보여 주고 15분 뒤에는 "오래 멈춘 작업"
  으로 올리던 것. "정지한 작업"으로 표시하고 멈춘 단계를 표시.
- **이어 받은 실행의 호출 기록** — 정지 후 이어 간 실행의 첫 호출이 단계 · 실행 번호 없이 기록되던 것.
- **새 파일의 줄 수** — 변경 내용 창에서 새 파일이 "+0줄"로 나오던 것.
- **제작 후 거절의 안내** — 코드가 만들어진 뒤 거절했는데 "실행되지 않았습니다"라고 나오던 문구.
- **한도 알림 위치** — 태블릿 폭에서 위쪽 구름의 이름표를 덮지 않게.
- **자세히 탭의 영어 화면** — 영어로 바꾸면 자세히 탭도 영어로 나옴. 서버가 한국어로 그린 문구를 화면에서 사전
  (`console/i18n_classic.js`)으로 바꾸고, 값이 갱신될 때마다 다시 바꿈. 사람과 AI가 쓴 글은 그대로 둠.
- **`clean-worktrees`가 실제로 정리하도록** — 변경이 든 작업 사본을 전부 건너뛰어 사실상 아무것도 지우지 못했음. 적용 · 폐기했거나
  닫힌 작업의 작업 사본은 브랜치와 함께 지움. 결정을 기다리는 결과물과, 충돌한 파일을 건너뛰고 적용해 일부러 남겨 둔 작업 사본은
  `--purge-reviewed`를 줘야 지움.
- **예전 기본 배정이 남아 있던 곳 정리** — 화면의 기본 배정 값, 자세히 탭 진행 문장의 기본 AI 이름, 데모 콘솔의 배정, 상태 기록
  문구("Antigravity executing"), 사용자 프로젝트의 git 기록에 남는 이름("AI DEV Bootstrap" → "Tribunal AI").
- **좁은 창** — 태블릿 폭에서 정지 버튼이 화면 밖으로 밀리던 것(버튼 줄에서 정지 버튼을 앞으로), 스크롤되는 폭에서 위쪽 막대
  뒤로 글자가 비치던 것, 한 줄 배치의 구름 속 화면에서 한도 알림이 숫자를 가리던 것.
- **데모 콘솔에 테스트 기록** — 핵 속 화면과 테스트 줄이 "기록 없음"이 아니라 결과와 출력을 보여 줌.
- **정지가 끝까지 지켜지도록** — 제작 중에 정지하면 CLI만 끊기고 실행은 계속되어(재시도 → 테스트 → 감리 → 판단) 작업이
  "완료"로 덮어써졌고, 자동 적용이 켜져 있었다면 원본에도 적용될 수 있었음. 이제 정지된 작업은 새 명령을 시작하지 않고,
  다음 단계를 계획하거나 마치거나 적용하지 않으며, 정지 상태가 다른 상태로 저장되지 않음. 끊긴 실행은 그 자리에 남아
  **이어서 시도**로 이어 감(`director resume <실행 번호>`는 그 실행만 끝까지 돌리고 작업은 정지 상태로 둠). 정지로 세워 둔
  실행은 그 프로젝트의 새 작업을 막지 않음.
- **명령줄 요약의 표기** — 예전 배정 그대로 `ANTIGRAVITY` · `CODEX REVIEW`로 찍히던 줄을 역할 이름(`MAKER` · `INSPECTOR`)으로.
- **감리 테스트의 복사본 위치** — 감리 AI가 제안한 테스트를 돌리는 버리는 복사본이 Tribunal의 실행 기록 폴더 안에 있어서,
  pytest가 대상 프로젝트가 아니라 Tribunal 자신의 `pytest.ini`와 가져오기 경로를 썼음. 복사본을 시스템 임시 폴더로 옮김.
- **되돌려진 적용의 안내** — 적용한 뒤 테스트가 통과하지 못해 원본을 되돌린 경우, 카드와 변경 내용 창에 그 사실과 건너뛴
  파일을 알려 줌(전에는 창에 "적용 보류"가 그대로 남고 카드에는 "적용 실패"만 나왔음).
- **정지한 작업의 카드** — 작업 정지로 멈춘 작업에도 멈춘 이유와 **이어서 시도**가 나옴(전에는 아무 안내도 없었음).
- **권한 보호 훅의 실행 명령 수정** — `python` 명령이 없는 컴퓨터(macOS 등)에서 훅이 시작되지 못하던 문제. 파일을 직접 쓰는 제작 방식에서만
  쓰이는 훅이라 기본 설정(파일 제안 방식)에는 영향이 없었음.
- 원본에서 넘어온 실패 테스트 7개의 원인을 모두 확인하고 해소([DEVELOPMENT.md](DEVELOPMENT.md) 1절).
- 멈춘 실행의 화면 표시용 상태 추가: 내가 거절한 실행은 "거절한 작업"으로(실행 기록 자체는 감사용이라 그대로).
- **AI가 빠졌을 때** (가짜 CLI로 돌려 보고 고침, 2026-11-23)
  - 요청의 첫 설계 호출(콘솔 채팅, 외부 지시, `director mission`)도 실행과 같이 넘김: 빠진 것으로 알려진 AI는 미리 바꾸고,
    한도 · 로그인 · 연결 · 시간 초과로 실패하면 상태를 기록한 뒤 다른 AI로 다시 부름. 바뀌면 "ARCHITECT 교체"로 알림.
    전에는 `director mission`이 traceback을 내며 죽고 그 AI의 상태도 기록하지 않았음. 대리 판단을 끈 경우는 고른 AI를 그대로 씀.
  - 제작: AI가 빠져서 난 실패는 `maker_attempts`를 쓰지 않고 남은 AI로 넘김(전에는 빠른 작업에서 두 AI가 빠지면 멀쩡한 세 번째
    AI를 써 보지도 않고 실패). 마지막 시도의 한도 소진도 기록함. 앞서 형식이 깨진 답을 낸 AI라도 쓸 수 있으면 남은 시도를 받음.
    쓸 수 있는 AI가 하나도 남지 않으면 실패가 아니라 "사용자 결정 필요"로 멈춤(다시 계획해도 소용이 없으므로).
  - AI가 빠져서 보류된 작업을 이어 가면, 그 단계를 멈춘 곳부터 다시 시도함(AI가 아직 빠져 있으면 다시 보류). 보안 정지는 다시 열지 않음.
  - 대리 판단을 끈 채 고른 AI가 빠지면(`MANUAL_ROLE_UNAVAILABLE`) 작업이 보류됨. 전에는 실패로 보고 다시 계획해서 같은 AI로
    다시 시도했음.
  - 멈춘 실행을 이어 갈 때 새 실행처럼 역할을 먼저 정함: 아직 빠진 AI를 한 번 불러 보고 넘기던 것을 없앰(가짜 CLI로 확인).
  - `director run`의 설계가 실패하면 남은 AI를 모두 차례로 시도함(전에는 하나만 더 시도). 그 AI가 감리도 맡고 있었으면 감리도 옮김.
    모두 빠지면 "사용자 결정 필요", AI가 빠진 게 아니라 답이 깨진 것뿐이면 설계 오류로 끝남(가짜 CLI로 세 경우 확인).
  - 역할이 다른 AI로 옮겨질 때마다 AI 상태 기록의 역할 표시도 바로 바꿈(전에는 실행 시작 때의 배정이 남았음).
  - 시간 제한을 AI별로도 정할 수 있음: `timeouts.ai: {codex: {maker: 900}}`. 한 AI에 맞춘 짧은 제한이 이어받은 AI까지 끊지 않게.
- 통과한 단계 없이 ARCHITECT가 "목표 달성"이라고 하면 작업을 완료가 아니라 미완료("끝내지 못함")로 끝냄. 이어서 진행할 수 있음.
- 작업 기록 없는 결과물도 적용한 뒤 한눈에 탭에 "최근 적용한 결과물"로 남아 변경 내용을 다시 볼 수 있고, 충돌을 건너뛰어
  남은 작업 사본은 거기서 지울 수 있음(`/result/clear`, 적용된 작업 밖 결과물만).
- `director run`의 끝 요약: 지시서가 만들어지지 않았으면 ARCHITECT를 PASS가 아닌 N/A로 보이고, 멈춘 이유를 `REASON:` 줄로 보임
  (전에는 설계가 시간 초과로 멈춰도 "ARCHITECT PASS"와 "SCOPE VIOLATION 1"만 나왔음). 넘기기 모드도 `[DEGRADED]`처럼 보임.
- 변경 내용 창: 충돌로 보류되면 충돌 파일 이름 뒤에 "다시 누르면 충돌 파일만 건너뛰고 적용" 안내를 붙임(전에는 파일 이름만).
  작업 기록 없는 결과물을 건너뛰기로 적용한 뒤에는 "건너뛴 파일의 AI 버전이 작업 사본에 남아 있습니다"를 보임(작업 카드가 없어 전에는 어디에도 없었음).
- 자세히 탭 프로젝트 고르기: 결과 줄이 `PROJECT_SELECTED: …` 같은 내부 코드 대신 "선택됨 · 경로" / "선택할 수 없습니다 · 이유"로 나옴(영어 화면 포함).
  결과 줄을 입력 폼 밖으로 옮김: 성공하면 폼이 접히면서 "선택됨" 줄도 함께 사라졌음.
- 적용한 결과물도 다시 볼 수 있음: 한눈에 탭 작업 카드에 적용 뒤에도 "변경 내용 보기", 자세히 탭의 "결과 확인"도 적용 뒤에 남음
  (적용하는 순간 저장한 변경 내용을 보여 주고, 지워진 작업 사본 위치는 보이지 않음). 자세히 탭에서 적용 · 폐기한 작업 결과물은 작업 카드에도
  적용됨 · 폐기됨으로 나오고, 카드의 적용 · 폐기 · 작업 사본 지우기도 그 기록을 따름(전에는 카드가 계속 "적용 대기"였음).
- macOS 폴더 선택 창: 콘솔이 백그라운드에서 돌아 macOS가 창을 막았음(-1713, "폴더 선택 창을 열지 못했습니다"). System Events가
  창을 띄우게 바꿈. 처음에 macOS가 제어 허용을 물을 수 있고, 막혀 있으면 자동화 설정에서 허용하라고 알려 줌.

  작업 결과 폴더 열기 · 프로젝트 폴더 열기를 배경색 있는 파랑 버튼으로.
- 지금 프로젝트 폴더를 Finder(Windows는 탐색기)로 열기: 자세히 탭 프로젝트 칸의 "폴더 열기", 한눈에 탭 위쪽의 폴더 아이콘.
  화면은 경로를 보내지 않고 서버가 가진 프로젝트만 엶(`/ops/open-project`, 로컬 토큰 필요). 사용자가 직접 눌러 확인함(2026-11-24).

  - 실행 방법: 제작 AI가 결과와 함께 적은 `run`(명령 · 종류 web/gui/terminal · 로컬 주소 · 열 html)이 있으면 그것,

    로컬 토큰 필요. 창은 끝나도 닫히지 않아 오류를 읽을 수 있음. Linux는 명령을 보여 주고 직접 실행하게 함.

    적용 전 결과물을 실행해 보기로 열어 브라우저에서 동작하는 것을 사용자가 확인함. 창이 뜨는 앱과 Windows · Linux는 아직.

### 콘솔 — 한눈에 탭

- 유리 구슬과 성운 구름으로 된 장면, 시작 연출, 현재 단계를 한 줄로.
- 작업 카드에서 바로 **승인 · 거절**, **멈춘 이유**, **변경 내용 보기 → 원본에 적용 · 폐기**. 작업 기록 없이 끝난 실행의 승인과
  결과물도 여기서 처리. 충돌한 파일만 건너뛰고 다시 적용.
- **통합 기록** — AI 호출, Tribunal이 한 일, 내 결정을 한 줄기로. 모든 줄이 상세 패널을 엶. 값은 해당 호출 · 회차의 시간 범위
  안에서만 연결하고, 없는 값은 "기록 없음".
- **구름 줌인**, **구름 속 화면**(그 AI의 호출 안에서 일어나는 일), **핵 속 화면**(Tribunal의 테스트, 실행 중 출력 포함).
- **AI 설정** — 모델, 추론 강도, 한도와 경고, 계정 표시(가린 이메일, 로그인 · 계정 변경 · 로그아웃은 터미널로).
- 예상 남은 시간(추정)과 조용한 시간 표시.
- 영어 · 한국어 화면.
- 글자 크기 6단계와 간격 · 모서리 단위 통일.
- 창이 보이지 않으면 서버에 묻지 않고, 가려진 장면은 그리지 않음.
- 대화의 시스템 기록 줄을 문장으로.

### 콘솔 — 자세히 탭

- 작업 영역을 먼저, 표시 내용은 사실대로. 화자와 역할 이름 정리, 휴대폰 화면 상단 막대.
- 한 화면 배치.
- AI 카드에 상태 · 역할 · 실제 사용량, 상세 상자는 한 번에 하나만 열리고 바깥을 누르면 닫힘.
- 거절한 실행을 열린 요청이 아니라 닫힌 것으로 표시.
