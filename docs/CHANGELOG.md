# 변경 이력

Tribunal AI는 [AI DEV DIRECTOR](https://github.com/digilogd-cmd/ai-dev-director) v3.1.8(MIT)에서 갈라져 나왔습니다. 이 문서는
그 뒤에 무엇을 바꿨는지, 원본에서 물려받은 것 중 무엇을 검증하지 않았는지를 적습니다.

## 원본에서 물려받은 것

흐름의 뼈대는 원본의 것입니다: 지시서, 파일 제안 방식의 제작, 격리 작업 사본, 범위 검사, 독립 감리, 자동 수정, 작업(여러 단계),
대리 판단 정책, 결과물 적용과 폐기, AI 상태 관리와 장애 시 교체, 호출 장부, 콘솔 서버와 브리지.

### 물려받았지만 이 프로젝트에서 검증하지 않은 것

코드는 있지만 실제로 돌려 확인한 적이 없습니다. 쓰기 전에 직접 확인이 필요합니다.

- **Windows · Linux 지원** — 원본은 Windows를 먼저 지원했습니다. 이 프로젝트는 macOS에서만 돌렸습니다. `start-companion.ps1`,
  `stop-companion.ps1`도 같습니다.
- **통과한 결과물의 자동 적용**(`autonomy.auto_apply`) — 시험은 모두 `--no-apply`로 하고 손으로 적용했습니다.
- **AI 장애 시 다른 AI로 교체**, **콘솔 재시작 뒤 작업 이어 하기**.
- **외부 주문 입구**(`/bridge/orders`)와 `allowed_projects`.
- **`director run` / `mission` / `resume` / `clean-worktrees`** — 실제 작업은 `director do`와 콘솔로만 돌렸습니다.
- **`scripts/`의 진단 · 재시도 도구**(`cli_diagnostics.py`, `retry_transport_run.py`, `test_role_cli_smoke.py`).
- **빈 폴더에서 새 프로젝트 시작하기** — 자동 준비 코드는 있지만 기존 프로젝트에서만 시험했습니다.

### 원본에 있었지만 뺀 것

- **TRIAD 연구 모드** — 세 AI가 독립 연구 → 상호 비판 → 종합 → 실험으로 이어지는 모드. 쓰지 않아서 코드, 테스트, 설계 문서를
  모두 지웠습니다(2026-11-22). 일반 흐름이 함께 쓰던 두 부분만 이름을 바꿔 남겼습니다: 읽기 전용 CLI 호출기(`core/cli_runner.py`)와
  프로젝트 파일 목록(`core/project_inventory.py`). 예전 데이터베이스에 남은 연구용 표는 그대로 두고 읽지 않습니다.
- **다시보기** — 지난 작업을 장면으로 재생하는 기능. 통합 기록과 상세 패널로 대신합니다.
- **원본의 마일스톤 문서** — 2026년 9월의 설계 · 안정화 기록. git 이력에 남아 있습니다.

## 바꾼 것

### 실행 환경

- macOS에서 동작하도록 고치고 실제 작업으로 검증.
- 콘솔 포트가 다른 프로그램에 잡혀 있으면 다음 빈 포트를 자동으로 사용. 이미 떠 있으면 그 주소를 알려 줌.
- 컴퓨터마다 다른 값은 git에 올리지 않는 `config.local.yaml`, `companion.local.json`에.
- 지어낸 작업으로 채운 읽기 전용 데모 콘솔(`scripts/demo_console.py`).
- 테스트가 만든 실행 폴더를 끝날 때 정리.

### 엔진

- **가벼운 호출** — Claude는 MCP 서버 · 스킬 없이 읽기 도구만(호출당 입력 약 51,000 → 8,000 토큰), Codex는 플러그인 · 메모리 ·
  훅 · 연결 앱 없이(감리 1회 약 52,000 → 7,000 토큰).
- **감리 AI의 독립 테스트** — MAKER가 쓴 테스트만으로 자기 코드가 통과하는 것을 막기 위해, INSPECTOR가 제안한 테스트를 Tribunal이
  실행. 완료 기준마다 테스트를 요청.
- **빠른 수정** — 테스트가 실패한 회차는 감리와 판단을 건너뛰고 바로 MAKER에게. 건너뛴 회차는 수정 횟수에 넣지 않음.
- **검증 시간 제한**을 설정으로(`verification.timeout_sec`). Claude의 설계 · 감리 호출은 출력 없는 시간 감시를 적용하지 않음.
- **판단에 테스트 출력 끝부분을 전달.**
- **돈 관련 코드 검사를 정밀하게** — 새 파이썬 파일이 직접 정의한 함수는 이름(`order_send` 등)만으로 멈추지 않음. 기존 파일
  수정, 모듈을 거친 호출, 이름이 다른 것에 연결될 수 있는 경우는 그대로 멈춤.
- **호출별 모델 · 추론 강도 기록.**
- **테스트 출력의 실시간 기록** — 테스트가 도는 동안 출력을 조각 단위로 남김. 판정에 쓰는 결과는 지켜볼 때와 아닐 때 동일.
- 모든 검증을 같은 환경(`PYTHONUNBUFFERED=1`)에서 실행.
- 멈춘 실행의 화면 표시용 상태 추가: 내가 거절한 실행은 "거절한 작업"으로(실행 기록 자체는 감사용이라 그대로).

### 이름

| 예전 | 지금 |

| AI DEV DIRECTOR | Tribunal AI |
| HEAD · 지휘 / BUILDER · 구현 / REVIEWER · 검수 | ARCHITECT · 설계 / MAKER · 제작 / INSPECTOR · 감리 |
| 흐름: 계획 → 구현 → 테스트 → 리뷰 → 결정 | 설계 → 제작 → 테스트 → 감리 → 판단 |
| 테스트 단계의 주체: DIRECTOR | TRIBUNAL |

| 방송 모드 | 전체 화면 |

옛 이름으로 저장된 데이터, 설정 키, 실행 기록은 계속 읽습니다(`core/role_names.py`).

### 콘솔 — 한눈에 탭

- 유리 구슬과 성운 구름으로 된 장면, 시작 연출, 현재 단계를 한 줄로.
- 작업 카드에서 바로 **승인 · 거절**, **멈춘 이유**, **변경 내용 보기 → 원본에 적용 · 폐기**. 작업 기록 없이 끝난 실행의 승인과
  결과물도 여기서 처리. 충돌한 파일만 건너뛰고 다시 적용.
- **통합 기록** — AI 호출, Tribunal이 한 일, 내 결정을 한 줄기로. 모든 줄이 상세 패널을 엶. 값은 해당 호출 · 회차의 시간 범위
  안에서만 연결하고, 없는 값은 "기록 없음".
- **구름 줌인**, **구름 속 화면**(그 AI의 호출 안에서 일어나는 일), **핵 속 화면**(Tribunal의 테스트, 실행 중 출력 포함).
- **AI 설정** — 모델, 추론 강도, 한도와 경고, 계정 표시(가린 이메일, 로그인 · 계정 변경 · 로그아웃은 터미널로).
- 예상 남은 시간(추정)과 조용한 시간 표시.
- 영어 · 한국어 화면.
- 글자 크기 6단계와 간격 · 모서리 단위 통일.
- 창이 보이지 않으면 서버에 묻지 않고, 가려진 장면은 그리지 않음.
- 대화의 시스템 기록 줄을 문장으로.

### 콘솔 — 자세히 탭

- 작업 영역을 먼저, 표시 내용은 사실대로. 화자와 역할 이름 정리, 휴대폰 화면 상단 막대.
- 한 화면 배치.
- AI 카드에 상태 · 역할 · 실제 사용량, 상세 상자는 한 번에 하나만 열리고 바깥을 누르면 닫힘.
- 거절한 실행을 열린 요청이 아니라 닫힌 것으로 표시.

## 미뤄 둔 것

- MAKER에게 보내는 지시 줄이기.
- 자세히 탭 스타일(`console/console.css`)에 남은 쓰이지 않는 규칙 정리.
- 감리 AI가 제안한 테스트는 파일 하나씩 따로 검사하므로, 프로젝트가 직접 만든 `order_send` 같은 이름의 함수를 가져다 쓰면 그
  테스트만 받아들여지지 않음(작업은 계속됨).
- 통합 기록은 화면이 갱신될 때마다 실행 폴더의 파일을 다시 읽음. 지금 규모에서는 문제없지만 기록이 많아지면 캐시가 필요.
