# 변경 이력

Tribunal AI는 [AI DEV DIRECTOR](https://github.com/digilogd-cmd/ai-dev-director) v3.1.8(MIT)에서 갈라져 나왔습니다. 이 문서는
그 뒤에 무엇을 바꿨는지, 원본에서 물려받은 것 중 무엇을 검증하지 않았는지를 적습니다.

## 원본에서 물려받은 것

흐름의 뼈대는 원본의 것입니다: 지시서, 파일 제안 방식의 제작, 격리 작업 사본, 범위 검사, 독립 감리, 자동 수정, 작업(여러 단계),
대리 판단 정책, 결과물 적용과 폐기, AI 상태 관리와 장애 시 교체, 호출 장부, 콘솔 서버와 브리지.

### 실제로 돌려 확인하지 않은 것

아래는 코드와 테스트는 있지만 **실제 작업이나 실제 화면으로 확인한 적이 없는 것**입니다. 실제로 확인한 것은 macOS에서
`director do`와 콘솔로 돌린 작업들입니다(통과, 자동 수정, 마침 검사에서 멈춤, 시작 전 · 제작 후 승인, 거절, 손으로 적용,
충돌 건너뛰기, 폐기, 두 단계로 이어지는 `standard` 작업과 그 결과물의 적용, 작업 사본의 제외 목록, 작업 정지 버튼, 콘솔을 껐다
켠 뒤 이어 하기, 자동 적용과 그 뒤의 작업 사본 · 브랜치 정리(두 단계 작업 포함), 정지한 작업의 작업 사본 지우기, 충돌 · 삭제 안내,
충돌을 건너뛴 적용과 그때 작업 사본이 남는 것, 적용 뒤 테스트가 실패해 되돌리는 경우, 감리 AI의 독립 테스트, 채팅의 "멈춰",
`director resume`, 정지한 작업의 이어서 시도).

**플랫폼**
- Windows · Linux 전체. `start-companion.ps1`, `stop-companion.ps1` 포함.

**흐름**
- `deep` 프로필, 세 단계 이상으로 이어지는 작업.
- 통과한 결과물의 자동 적용 중 `on_done`(`on_pass`는 확인).
- 감리 AI의 독립 테스트가 **실패해서** 수정 회차로 이어지는 경우(제안한 테스트가 돌아 통과하는 것은 확인).
- 제작 재시도(`maker_attempts`), 출력 한도에 걸렸을 때의 압축 재시도, 마지막 시도에서 다른 AI로 넘기기.
- 시간 제한에 실제로 걸리는 경우: 3분 넘게 걸리는 Claude 호출, 검증 시간 초과, 출력 없는 CLI 종료.
- 실패(FAIL) · 시간 초과(TIMEOUT)로 끝나는 실행.

**AI를 쓸 수 없을 때**
- 한도 소진 · 로그인 풀림으로 AI 하나가 빠졌을 때 역할 옮기기(시작 시점, 실행 도중, 대리 판단을 끈 경우 모두).
- AI 둘 이상이 빠져 멈추는 경우.

**정지와 재개**
- 정지한 작업이 여러 단계 중간이었을 때 이어서 시도, 콘솔 밖(`director mission`)에서 돌린 작업의 정지.

**승인과 결과물**
- 제작 후 승인 요청을 거절하는 경우.
- 결제 SDK 가져오기 · 결제 호출 · 모듈을 거친 주문 호출로 돈 관련 코드 검사에 걸리는 경우(함수 이름으로 걸리는 경우만 확인).
- 작업 기록 없이 끝난 결과물을 충돌 건너뛰기로 적용하는 경우.

**프로젝트 준비와 설정**
- git이 없는 폴더, 빈 폴더, 테스트가 하나도 없는 프로젝트에서 시작하기.
- 프로젝트별 검증 명령(`projects:`), 빌드 · 린트 명령.
- 직접 정한 포트가 잡혀 있을 때의 동작, `TRIBUNAL_PORT`.

**명령줄과 도구**
- `director run` / `mission` / `status` / `resume` / `clean-worktrees`.
- 외부 주문 입구(`/bridge/orders`)와 `allowed_projects`.
- `scripts/`의 `cli_diagnostics.py`, `retry_transport_run.py`, `test_role_cli_smoke.py`.
- 데모 콘솔: 서버가 뜨고 기록을 내주는 것까지만 확인. 최근 화면 변경 뒤의 모습은 보지 않음.

**콘솔**
- AI 설정의 로그인 · 계정 변경 · 로그아웃 버튼(일부러 누르지 않음), 이메일 전체 보기.
- 한도가 임박했을 때의 경고.
- 한 AI에 여러 역할을 맡겼을 때의 "감리 독립성 낮음" 표시.
- 영어 화면에서의 통합 기록 · 구름 속 · 핵 속 화면.
- 좁은 창 · 휴대폰 크기에서의 통합 기록과 구름 속 · 핵 속 화면.
- 움직임 줄이기 설정, WebGL을 쓸 수 없을 때의 대체 그림에서 줌인과 구름 속 화면.
- 전체 화면 모드와 새 기능의 조합.
- 도구를 많이 쓰는 호출(기록 200건 초과 포함), 오류가 난 도구 호출이 구름 속 화면과 상세 패널에 나오는 모습.
- 핵 속 화면에서 실패하는 테스트가 실시간으로 나오는 모습.
- 자세히 탭의 폴더 선택 창, 새 대화, 결과물 적용, 작업 사본 폴더 열기.

### 원본에 있었지만 뺀 것

- **TRIAD 연구 모드** — 세 AI가 독립 연구 → 상호 비판 → 종합 → 실험으로 이어지는 모드. 쓰지 않아서 코드, 테스트, 설계 문서를
  모두 지웠습니다(2026-11-22). 일반 흐름이 함께 쓰던 두 부분만 이름을 바꿔 남겼습니다: 읽기 전용 CLI 호출기(`core/cli_runner.py`)와
  프로젝트 파일 목록(`core/project_inventory.py`). 예전 데이터베이스에 남은 연구용 표는 그대로 두고 읽지 않습니다.
- **다시보기** — 지난 작업을 장면으로 재생하는 기능. 통합 기록과 상세 패널로 대신합니다.
- **원본의 마일스톤 문서** — 2026년 9월의 설계 · 안정화 기록. git 이력에 남아 있습니다.

## 바꾼 것

### 실행 환경

- macOS에서 동작하도록 고치고 실제 작업으로 검증.
- 콘솔 포트가 다른 프로그램에 잡혀 있으면 다음 빈 포트를 자동으로 사용. 이미 떠 있으면 그 주소를 알려 줌.
- 컴퓨터마다 다른 값은 git에 올리지 않는 `config.local.yaml`, `companion.local.json`에.
- 지어낸 작업으로 채운 읽기 전용 데모 콘솔(`scripts/demo_console.py`).
- 테스트가 만든 실행 폴더를 끝날 때 정리.

### 엔진

- **가벼운 호출** — Claude는 MCP 서버 · 스킬 없이 읽기 도구만(호출당 입력 약 51,000 → 8,000 토큰), Codex는 플러그인 · 메모리 ·
  훅 · 연결 앱 없이(감리 1회 약 52,000 → 7,000 토큰).
- **감리 AI의 독립 테스트** — MAKER가 쓴 테스트만으로 자기 코드가 통과하는 것을 막기 위해, INSPECTOR가 제안한 테스트를 Tribunal이
  실행. 완료 기준마다 테스트를 요청.
- **빠른 수정** — 테스트가 실패한 회차는 감리와 판단을 건너뛰고 바로 MAKER에게. 건너뛴 회차는 수정 횟수에 넣지 않음.
- **검증 시간 제한**을 설정으로(`verification.timeout_sec`). Claude의 설계 · 감리 호출은 출력 없는 시간 감시를 적용하지 않음.
- **판단에 테스트 출력 끝부분을 전달.**
- **돈 관련 코드 검사를 정밀하게** — 새 파이썬 파일이 직접 정의한 함수는 이름(`order_send` 등)만으로 멈추지 않음. 기존 파일
  수정, 모듈을 거친 호출, 이름이 다른 것에 연결될 수 있는 경우는 그대로 멈춤.
- **호출별 모델 · 추론 강도 기록.**
- **테스트 출력의 실시간 기록** — 테스트가 도는 동안 출력을 조각 단위로 남김. 판정에 쓰는 결과는 지켜볼 때와 아닐 때 동일.
- 모든 검증을 같은 환경(`PYTHONUNBUFFERED=1`)에서 실행.
- **기본 역할 배정 변경** — 제작 Codex, 감리 Antigravity(원본은 제작 Antigravity, 감리 Codex). AI 하나를 쓸 수 없을 때 역할을 옮기는
  규칙을 배정과 무관하게 동작하도록 고침.
- **작업 사본에 들어간 추적 안 된 파일을 기록하고 화면에 표시**, **제외 목록 설정**(`snapshot_exclude`), **폐기할 때 실행 브랜치도 삭제**.
- **여러 단계 작업의 변경 내용 보기** — 결과물을 적용하면 앞 단계의 파일도 함께 쓰이는데 화면에는 마지막 단계의 변경만
  나오던 문제. 적용 전 화면이 실제로 쓰일 파일 전체와 원본 대비 변경을 보여 주고, 몇 단계의 변경인지 표시.
- **작업 사본과 실행 브랜치 자동 정리** — 결과물을 원본에 적용하면 그 작업의 모든 단계의 작업 사본과 브랜치를 지움(충돌한 파일을
  건너뛴 경우는 남기고, 다 쓴 뒤 결과물 카드의 **작업 사본 지우기**로 정리). 폐기하면 앞 단계의 것도 함께 지움. 아무것도 통과하지 못하고 멈춘 작업은 카드의 **작업 사본 지우기**로 정리.
  적용할 때 쓴 파일과 변경 내용은 실행 기록에 남아 작업 사본이 없어도 다시 볼 수 있음.
- **정지가 끝까지 지켜지도록** — 제작 중에 정지하면 CLI만 끊기고 실행은 계속되어(재시도 → 테스트 → 감리 → 판단) 작업이
  "완료"로 덮어써졌고, 자동 적용이 켜져 있었다면 원본에도 적용될 수 있었음. 이제 정지된 작업은 새 명령을 시작하지 않고,
  다음 단계를 계획하거나 마치거나 적용하지 않으며, 정지 상태가 다른 상태로 저장되지 않음. 끊긴 실행은 그 자리에 남아
  **이어서 시도**로 이어 감(`director resume <실행 번호>`는 그 실행만 끝까지 돌리고 작업은 정지 상태로 둠). 정지로 세워 둔
  실행은 그 프로젝트의 새 작업을 막지 않음.
- **명령줄 요약의 표기** — 예전 배정 그대로 `ANTIGRAVITY` · `CODEX REVIEW`로 찍히던 줄을 역할 이름(`MAKER` · `INSPECTOR`)으로.
- **감리 테스트의 복사본 위치** — 감리 AI가 제안한 테스트를 돌리는 버리는 복사본이 Tribunal의 실행 기록 폴더 안에 있어서,
  pytest가 대상 프로젝트가 아니라 Tribunal 자신의 `pytest.ini`와 가져오기 경로를 썼음. 복사본을 시스템 임시 폴더로 옮김.
- **되돌려진 적용의 안내** — 적용한 뒤 테스트가 통과하지 못해 원본을 되돌린 경우, 카드와 변경 내용 창에 그 사실과 건너뛴
  파일을 알려 줌(전에는 창에 "적용 보류"가 그대로 남고 카드에는 "적용 실패"만 나왔음).
- **정지한 작업의 카드** — 작업 정지로 멈춘 작업에도 멈춘 이유와 **이어서 시도**가 나옴(전에는 아무 안내도 없었음).
- **권한 보호 훅의 실행 명령 수정** — `python` 명령이 없는 컴퓨터(macOS 등)에서 훅이 시작되지 못하던 문제. 파일을 직접 쓰는 제작 방식에서만
  쓰이는 훅이라 기본 설정(파일 제안 방식)에는 영향이 없었음.
- 원본에서 넘어온 실패 테스트 7개의 원인을 모두 확인하고 해소([DEVELOPMENT.md](DEVELOPMENT.md) 1절).
- 멈춘 실행의 화면 표시용 상태 추가: 내가 거절한 실행은 "거절한 작업"으로(실행 기록 자체는 감사용이라 그대로).

### 콘솔 — 한눈에 탭

- 유리 구슬과 성운 구름으로 된 장면, 시작 연출, 현재 단계를 한 줄로.
- 작업 카드에서 바로 **승인 · 거절**, **멈춘 이유**, **변경 내용 보기 → 원본에 적용 · 폐기**. 작업 기록 없이 끝난 실행의 승인과
  결과물도 여기서 처리. 충돌한 파일만 건너뛰고 다시 적용.
- **통합 기록** — AI 호출, Tribunal이 한 일, 내 결정을 한 줄기로. 모든 줄이 상세 패널을 엶. 값은 해당 호출 · 회차의 시간 범위
  안에서만 연결하고, 없는 값은 "기록 없음".
- **구름 줌인**, **구름 속 화면**(그 AI의 호출 안에서 일어나는 일), **핵 속 화면**(Tribunal의 테스트, 실행 중 출력 포함).
- **AI 설정** — 모델, 추론 강도, 한도와 경고, 계정 표시(가린 이메일, 로그인 · 계정 변경 · 로그아웃은 터미널로).
- 예상 남은 시간(추정)과 조용한 시간 표시.
- 영어 · 한국어 화면.
- 글자 크기 6단계와 간격 · 모서리 단위 통일.
- 창이 보이지 않으면 서버에 묻지 않고, 가려진 장면은 그리지 않음.
- 대화의 시스템 기록 줄을 문장으로.

### 콘솔 — 자세히 탭

- 작업 영역을 먼저, 표시 내용은 사실대로. 화자와 역할 이름 정리, 휴대폰 화면 상단 막대.
- 한 화면 배치.
- AI 카드에 상태 · 역할 · 실제 사용량, 상세 상자는 한 번에 하나만 열리고 바깥을 누르면 닫힘.
- 거절한 실행을 열린 요청이 아니라 닫힌 것으로 표시.

- MAKER에게 보내는 지시 줄이기.

  테스트만 받아들여지지 않음(작업은 계속됨).
- 통합 기록은 화면이 갱신될 때마다 실행 폴더의 파일을 다시 읽음. 지금 규모에서는 문제없지만 기록이 많아지면 캐시가 필요.
